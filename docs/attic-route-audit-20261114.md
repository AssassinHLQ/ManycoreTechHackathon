# 阁楼线入口、进度与宇宙线关系审计

日期：2026-11-14。依据当前脚本及独立测试存档；没有通过用户的正式存档推进剧情。

## 玩家现在怎样进入

1. 标题页「开始探索」进入青岚星的宇宙线。
2. 在赭崖、沧波、悬晶扫描三枚坐标，解除玄渊扫描限制。
3. 扫描玄渊条目，出现「黑洞前奏」结局页。
4. 点击「回到阁楼，把这段慢时间还给自己」，进入阁楼。

还有一个可用但没有标成正式游玩入口的途径：标题页点「自动演示」，按 Esc 退出演示后，玩家会留在可以自由操作的阁楼。完整演示也会把控制权交还给玩家。演示调用真实场景和交互，并非与游戏进度完全隔离的预览。

宇宙结局已被存档记录后，重新「开始探索」不会自动再弹一次结局，也没有持久解锁的阁楼入口按钮。因此当前设计的可发现性和重访路径都不完整。

对应代码：`hud.gd::_build_menu/_build_ending`、`main.gd::start_game/discover/start_demo/stop_demo`、`main.gd::_update_scanner/missing_clues`。

## 阁楼中的实际流程

| 对象 | 实际触发 | 前置条件与结果 |
| --- | --- | --- |
| 四扇门 | 走近对应门按 E | 分别进入 snow/cloud/firefly/alley；没有天气或纪念门槛 |
| 黄铜天气旋钮 | 走近按 E | 云海、森林、雨巷、雪夜的窗景轮换；不改变四门目的地 |
| 世界回程门 | 走近按 E | 回到对应阁楼门前；仅走过门槛不会触发 |
| 雪夜纪念 | 对齐三面冰镜 | 自动归架；冰钓是另一条独立玩法 |
| 云海纪念 | 完成三处云灯装置 | 自动归架；另有云舟、浮标、绞盘等交互 |
| 森林纪念 | 收集三处萤火装置 | 自动归架 |
| 雨巷纪念 | 对齐三处水兽铜阀 | 自动归架，并让阁楼窗台燕子出现 |
| 茶席 | 茶壶旁按 E 三次 | 烧水、投茶、出汤；可以提前泡，四件纪念与茶都完成后，提示才判定主线完成 |
| 穿衣镜 | 靠近按 E | 直接进入镜界，没有四件纪念门槛 |
| 棱镜之心 | 镜界中央靠近按 E | 直接领取；当前没有先击败镜界三波敌人的条件 |
| 镜牢 | 镜界东侧门旁按 E | 自愿参加的独立战斗路线；门没有先取心或通关镜界的解锁条件 |

四门、镜界、小游戏及镜牢不是线性强制解锁链。「下一件值得做的事」提供建议顺序，不等同于门禁。

## 目前两条线怎样相连

- 有明确实现的是「宇宙结局 → 阁楼」和阁楼中暂停 1020 秒恒星倒计时。
- 宇宙知识保存在 `starward_knowledge.json`；阁楼纪念、茶席、成就等保存在 `starward_progress.json`。两边各自保存，并没有形成相互解锁的知识链。
- 宇宙三枚棱镜坐标与镜界棱镜之心主题相似，但 `has_prism_heart` 不参与宇宙坐标检查和玄渊结局条件。四件纪念同样不会改变宇宙任务。
- `leave_attic()` 存在，但没有绑定可见按钮、门或正常玩家输入。玩家目前需要 Esc → 返回标题 → 开始探索回宇宙；这会重新开始本轮，保留已存的知识。
- 因此当前是一个结局串接两个玩法的结构，尚未实现玩家来回带线索的双线叙事。

## 本轮修复

1. 纪念使用显式世界 ID → 成就 ID 映射，森林、雨巷正确显示在成就页；读取旧存档时迁移 `keepsake_firefly/alley`，避免和目录中的 `keepsake_forest/rain` 重复计数。旧代码的纪念本身可以恢复，错的是成就目录识别。
2. 读取 `tea_full` 后恢复三步茶席、蒸汽与茶杯，避免完成主线后重启又被提示泡茶。雨巷纪念也恢复窗台燕子。
3. 离开阁楼、返回标题、重开游戏统一清除阁楼/口袋世界标记，恢复宇宙光照；清理云舟、望远镜、钓鱼、镜牢和未完成引导的临时状态。未完成引导隐藏时不会误记为看完。
4. 手册、新手提示改为真实的按 E 进入和返回逻辑；修正镜界拾取与镜牢战斗的说明，不再宣称并不存在的镜界三波解锁。
5. 冒烟测试显式使用独立的进度路径，避免读取玩家的阁楼里程碑。
6. 棱镜之心拾取时隐藏整件生成模型、上下发光核心和附属灯光；重载后原件也保持隐藏，已拾取的台座不再响应领取。

本轮没有新增剧情、门禁或两条线之间的奖励规则，也没有新增直返宇宙入口。

## 建议的双线结构（尚未实现）

建议把阁楼作为旅途中可以重访的记忆枢纽，在宇宙第一条正式发现后给出可发现入口，并在阁楼提供明确返航操作。返航需要恢复原行星/站内的安全位置和剩余轮回时间；不能简单把玩家丢到飞船世界坐标的 +Y 上。

采用「宇宙发现 → 阁楼中出现对应记录或物件 → 阁楼提供可以验证的航行线索 → 回宇宙验证」的闭环。四个远方可以在风、寒冷、发光植被、水声等体验上与星球呼应，但应明确哪些是记忆、哪些是真实地点，避免四门与三枚坐标生硬一一绑定。

可供确认的具体呼应如下；以下均为建议，不是已有任务条件：

| 阁楼内容 | 宇宙对应体验 | 可以形成的反馈 |
| --- | --- | --- |
| 云海、风琴礁 | 青岚风车塔的风与观测 | 塔中记录出现相同风律；在阁楼听全后，小册标出一处值得复查的观测点 |
| 雪夜、冰镜 | 白曜冰原与悬晶折射 | 让冰镜与宇宙遗迹复用可辨认的光路图案，小册解释这种图案的意义 |
| 萤火森林 | 玄圃的暗处发光植被 | 两边出现相同发光节奏；阁楼提供辨认方法，宇宙里据此寻找回声 |
| 雨巷、水钟 | 沧波水下的音乐 | 水钟与研究记录共享节拍，玩家回沧波能认出此前听不懂的信号 |
| 镜界、棱镜之心 | 悬晶空间折叠与三枚坐标 | 在记录中交代两类棱镜的关系，让最后一次归家回应宇宙线的问题 |

旅行架和旅行小册应同时展示两边已有进度，让玩家看见带回的发现改变了什么。棱镜之心的来源和宇宙棱镜需要补上一条明确记录；是否影响最后的结局表达，要先确定故事含义。泡茶、钓鱼和小游戏可继续保持自愿，不必强制成为宇宙主线门槛。

## 验证范围

`tests/attic_flow_test.gd` 使用独立知识/进度文件，驱动与扫描完成相同的发现事件，实际点击结局页按钮、四门 E 交互和暂停菜单按钮；同时验证新旧成就存档、茶席视觉、燕子、标题重开后的计时与重力状态，以及「演示 → Esc → 可玩阁楼」。此测试不代替人工驾驶飞船完成全过程。

修复前，该流程测试的 19 项断言有 11 项失败；四门及结局入口本身可用。修复后的测试增加了门交互、茶席视觉和演示退出的断言。

最终流程测试 32 项全部通过；`progress_test`、`pocket_world_test`、`keepsake_model_test`、`handbook_test`、`guide_boat_test`、`tea_court_test`、`smoke_test` 均通过，无脚本错误。
