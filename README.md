# 借一扇晴天

一个使用 **Godot 4 + GDScript** 制作的原创第一人称太空探索原型。游戏内标题为《借一扇晴天》（只有中文名）。星球、归航站、界面、模型、材质、文本与程序音频均在本项目中程序化生成；烤棉花糖是唯一保留的具体玩法致敬。

地下洞穴、可进入的建筑内部、六廊归航站中央枢纽、量子规则与动态天体都在同一个场景、同一套程序化管线中生成，不需要切换关卡。

## 启动

- Windows：双击 `启动游戏.bat`（用编辑器运行）。
- Windows 单文件版：**已停用**，本项目只发布网页版。exe 单个约 105 MB 太占空间，产物已删除；`导出exe.bat` 与 Windows 导出预设保留但不再使用，也不要再跑。
- 网页版：双击 `导出网页版.bat` 生成 `build/web/`，再双击 `启动网页版.bat` 本地预览。
- Godot：导入本目录的 `project.godot`，按 **F5** 运行主场景。
- 已验证引擎：**Godot 4.7.1**。项目使用 Compatibility 渲染器，无 C#、插件或外部素材依赖。

## 探索闭环

1. 在青岚星的飞船旁醒来（出生点在村口路上、飞船后侧，正对风车塔），按住 **F** 扫描旧观测符文。
2. 登上飞船，在扩大十倍的太阳系中自由飞行；每颗星球都有独立重力、起伏地形与标志场景。途中可低速靠近归航站，自动对接后进入六廊中央枢纽。
3. 前往赭崖星、沧波星、悬晶星，记录三枚棱镜坐标。
4. 前往星图最外侧的玄渊星，解除加密并扫描玄渊之核。
5. 恒星在 **17 分钟**后进入超新星阶段。轮回会重置位置和资源，但航海日志永久保留。

结局后仍可继续自由探索。

三条可选线索贯穿整个世界：

- 青岚星、赭崖星与悬晶星的地表各有一个真实挖穿地形的洞口，沿螺旋坡道下到洞室，可以扫描三处隐藏回声。
- 青岚星的风车塔与沧波星的浮冰研究站可以直接推门进入，室内各有一处可扫描的日志。
- 悬晶星上的量子碎岩只在无人注视时迁移；盯住它、扫描它，它会留在原地。理解量子规则后，它会永久安定。
- 一颗彗星会周期性穿过星系，沧波星的潮汐也会随轮回上涨。

## 归航站

归航站（HOMECOMING STATION）是一座绕青岚星约 2600 米极轨道缓慢公转的原创环状空间站（约 26 分钟一圈，离行星表面约 2200 米）。半径约 280 米的连续方截面外环围绕中央枢纽缓慢旋转，六条各约 225 米的方截面栖息臂以 60° 间隔从枢纽伸向外环，内部对应六条约 210 米长的可步行放射走廊。

- **外观**：一整圈连续的方截面外环、六条带方肋的栖息臂、末端方盒指挥舱；中央球状枢纽上下贯穿一根总长约 490 米的竖向主塔——下段是带 36 米笼架与青色内芯的能源核心，中段是 150 米环箍桁架与四节舱段（含检修车），上段是分段指挥塔，对接口升到塔顶并带捕获环、四只夹爪与四座导引灯柱。每条臂都有方窗带、方环肋、纵向板缝、方形检修舱门、姿控喷口、外挂方桁架与散热管。靠近时可见「归航站」「指挥塔」「能源中枢」「对接塔」标牌。环形与放射结构的视觉组织参考《星际穿越》的环形空间站，但所有几何、材质、标识与布局均为本项目重新构建。
- **方臂外壳是"开口方管"**：六条栖息臂的外壳只有朝外的四个面，没有端盖、也没有朝内的面。这一条很关键——外壳端面本来正好落在半径 30 的门平面上，实心体时从枢纽看每扇门后面都是一堵灰绿色的墙（而且它只在 layer 4 上挡飞船，玩家会直接"穿过墙"进走廊）；做成开口管后，门后能直接看到走廊，站外看外壳依旧完整，舷窗也照旧能看到真实星空（朝内的面不存在，永远是背面剔除）。碰撞仍是外臂的实心 BoxShape3D（layer 4），飞船进不来。
- **对接**：飞船从指挥塔顶上方低速靠近，距离对接口 **24 米内且相对站点速度低于 18 m/s** 会自动磁力对接；对接口有捕获环、四只夹爪与橙色导引灯；对接后自动补给推进剂、船体与宇航服氧气。脱离对接后有 3 秒冷却，不会立刻被重新吸附。
- **进站**：对接后按 **E** 进入空间站中央枢纽；**Space** 脱离对接。进入与离开都在 `main.tscn` 同一个场景内完成，不加载新关卡。
- **六廊中央枢纽**：直径约 60 米的中央大厅，A–F 六扇放气门分别通往医疗环、科研环、居住环、工业环、后勤环、观景环；门楣有中文扇区牌与警示门槛。放气门是左右对开的两扇门板：玩家走到离门 9 米以内时，门板用 0.55 秒从中缝滑向两侧门框，碰撞体跟着门板一起移动，所以门没开完时人会被实实在在挡住；玩家深入走廊后门在身后合上，站在门洞里时不会夹人。门后走廊只在玩家进入对应扇区时显示。枢纽内有中央升降梯、旋转的全息站体沙盘、环区态势屏、数据屏、长凳、植栽、地面导引线与气闸控制台。
- **走廊与舱室**：每条走廊由 12 间原创功能舱室组成，六条共 72 间；左右分别为医疗舱/温室、食堂/居住舱、档案室/通信室、实验舱/维修间、储藏舱/图书室、休憩厅/观景廊；每条走廊远端都有中央大厅与舰桥。
- **硬表面细节**：墙面有深浅两层内嵌板、检修口、螺栓、通风格栅、线槽、扶手、管线与灯带；天花有横梁、桥架与管束；地面有分缝与格栅；放气门带液压杆、警示条、随左门扇一起滑开的门号与中文扇区牌；枢纽有环梁、升降梯门框/呼叫面板与状态屏。
- **枢纽细节合并网格**：中央枢纽额外有一层硬表面细节——甲板同心分缝与排水格栅、天花放射电缆桥架与环向管束、12 处灯具外壳与吊杆、环墙踢脚/竖肋/环带/螺栓/检修格栅/接线箱/扶手、升降梯裙板与呼叫面板、门柱面板/液压软管/门楣状态灯带，合计 721 个盒子。它们**合并成一张 8 材质 ArrayMesh**，只占 1 个节点、6 次绘制、8,652 个三角形，构建耗时约 13 ms；不带碰撞（纯装饰），并且逐三角面校验过绕序朝外。
- **静态网格合并（站内 + 站外）**：启动时把静态硬表面按"材质签名 + 空间分块"烘焙成多材质网格，共合并 **3,914 个** `MeshInstance3D`——走廊 1,497 个 → 42 块、枢纽 802 个 → 26 块、站外（六条外臂/主塔/端舱/检修车/设施）1,403 个 → 116 块、外环细节 212 个 → 72 块。全站网格节点 **11,655 → 722**、总 surface **11,660 → 2,636**；飞到站点附近（只画外环与站外）可绘制批次 **≈1,630 → ≈680**，六条走廊共享同一批网格资源。合并只搬运顶点：各批次的三角形数与"含切段的预期值"逐面完全相等，法线仍是单位长度；碰撞（走廊 244 个 shape、外壳 40+ 个）、灯光、标签、会旋转的全息沙盘与外环、会滑动的门扇、要切换可见性的端舱、会闪的信标材质都在合并之外。headless A/B 实测：开合并建场 3,549 ms、关合并 3,537 ms，**合并几乎不增加加载时间**。
- **为什么必须分块**：兼容渲染器每个对象只取 `rendering/limits/opengl/max_lights_per_object` 盏灯（默认 8），而站内平均 7.8 米就有一盏灯。整条 213 米走廊合成一个对象时，门口的灯会被一百米外的灯挤掉，门洞看进去就是一片黑。所以长方体按 24 米（站外 60 米）切段、细长圆柱沿轴切段、圆环与圆盘这类切不动的大件保持独立节点（合并前它们本来就是一个对象），并把每对象灯上限提到 **16**（`project.godot`）；实测走廊最坏的分块范围内 11 盏灯 ≤ 16，站外只有 3 盏灯。要整体回退这套合并，把 `station.gd` 里的 `MERGE_STATIC_MESHES` 改成 `false` 即可。
- **内部陈设**：观景廊有观测望远镜、倾斜星图控制台、贴窗软凳与角落植栽；中央大厅有带辐条的全息站体沙盘、环形地面嵌线、三座长凳与壁柱/顶梁；舰桥有两组驾驶台、侧壁系统屏与独立指挥官座椅。
- **真实舷窗**：每间舱室、每条中央大厅与舰桥都有透明玻璃窗和碰撞；窗外是同一场景中的真实星空、行星、太阳与旋转外环，不是贴图或假背景。
- **人造重力**：站内使用 0.70 G 人工重力，跳跃、喷气背包与楼层碰撞按站体局部坐标计算。
- **气闸**：中央枢纽的气闸控制台按 **E** 可返回停靠中的飞船；R 在站内会把角色送回中央枢纽气闸，不会把人传到行星表面。

## 量子与动态天体

- **量子碎岩**（悬晶星）：在五个候选坐标之间迁移，只有被摄像机实际看见并且视线未被遮挡时才会静止。未被观测 2.4 秒后传送；扫描并写入日志后永久锁定。
- **曳光彗星**：沿倾斜椭圆轨道周期穿过星系，只保留一条离子尾与一条尘埃尾，HUD 与星图都有标记。
- **沧波星潮汐**：海面高度随轮回上涨，研究站的高脚结构会逐渐被海水围住。
- **太阳近距 LOD**：飞近太阳时表面黑子与日珥逐渐显现；远离后自动淡出，不增加远处视角的负担。飞船滚轮可拉长焦观察。

## 手机 / 触屏

- **自动识别**：Android / iOS、带触摸屏的设备，以及手机浏览器会自动出现触屏层；网页版也可用 `?touch=1` 强制开启。桌面键鼠玩家不会看到这些按钮。
- **左侧摇杆**：徒步移动 / 飞船平移，支持模拟量力度。
- **右侧空白拖动**：转动视角，不影响按键区。
- **圆形按键**：徒步为跳跃 / 喷气 / 互动 / 扫描 / 头灯；飞船自动切换为起飞或着陆 / 离船 / 上升 / 下降 / 加力 / 制动 / 自动航行，并有星图 / 日志 / 菜单。

## 启动耗时（网页版首屏的关键）

启动曾是一帧内同步构建整场，网页是单线程 wasm，会明显放大。已做的三项优化：

- **跨帧渐进式建场**（`main.gd`）：`_ready` 不再一口气建完，而是把建场切成 15 个阶段，每阶段之间 `await get_tree().process_frame` 让出一帧渲染。阶段顺序与原同步版本完全一致，依赖关系不变；服务节点（设置 / 音频 / HUD / 触屏）在最后创建。建场期间 `world_ready == false`，`_process` 直接返回（此时 `home` / `menu_camera` / 火焰都还没建出来）。
  - 单帧最贵分片从「整场约 3,969 ms」降到约 **286 ms**（空间站），其次音频合成 224 ms、青岚星 189 ms；整场合计约 1.2 s，分 15 帧摊开。
  - 测试与外部脚本用 `await game.await_world_ready()` 等待建场完成（已就绪时立即返回，可重复调用）。19 个测试脚本已按此更新。
  - 排查首屏卡顿时把 `main.gd` 的 `BUILD_TIMING` 改为 `true`，会打印每个分片的毫秒数。
- **地形碰撞延迟建**：`create_trimesh_shape()` 原本是启动最贵的一项（home/ember/shard 各约 155 ms、五颗合计约 530 ms）。现在改成飞船或玩家进入 4 倍半径时才建（`_ensure_terrain_collision()`），落地前早就建好。
- **远距单发音效按需合成**：`ping/creak/radio/moan` 四段样本第一次真的播放时才生成，启动不再为它们付逐样本合成的钱。

headless A/B（各取 3 次最小值，本机）：**行星阶段 2,735 → 1,231 ms；整场构建 5,572 → 3,969 ms**（均为「工作总量」，现已进一步切成跨帧分片）。

> 还剩一项没动，属于引擎固有：Godot 4 的 39 MB wasm 编译（约十几秒，浏览器会因此提示「此网页拖慢了 Firefox」）。跨帧建场已经把「应用层卡死」消掉了，剩下的是引擎编译期的等待——那需要换导出策略（如多线程导出 + COOP/COEP 头）才能再优化。

### 灵感借鉴

- **太空探索与时间循环类型**：包括 Outer Wilds 在内的探索类作品带来了类型与体验层面的启发（限时轮回、恒星爆发、量化观测、篝火烤棉花糖等玩法母题）。**未使用**其名称、角色、剧情、地点、界面、模型、文本、音乐或音效；游戏标题《借一扇晴天》、十颗天体名（青岚星 / 赭崖星 / 沧波星 / 悬晶星 / 玄渊星 / 白曜星 / 磐砂星 / 苔垣星 / 硫坞星 / 缄默星）、舱室名与全部标牌均为本项目原创。
- **环状空间站外观**：连续方截面外环、六条方截面放射栖息臂与中央枢纽的视觉组织参考了《星际穿越》（Interstellar）中的环形空间站/Endurance；**未使用**其名称、标志、角色、剧情、模型、贴图、镜头或任何美术素材。归航站的尺寸、连续外环、六条 225 米栖息臂、六廊布局、舱室、标牌与内部细节均为本项目重新构建。
- **六廊放射居住站布局**：归航站「中央枢纽 + 六条放射走廊 + 每廊十二舱室、公共大厅与舰桥」的空间母题参考了 Arknights 中罗德岛等移动舰船的视觉组织方式；**未使用**其名称、标志、角色、剧情、房间名或任何美术素材。站名「归航站」、A–F 扇区名、全部舱室名、平面布局、家具与标牌均为本项目原创。
- 其余为通用科幻视觉语言：环形空间站、旋转人造重力、舷窗观景、实用主义舱室与暖色灯带。

### 美术来源

- 程序化低多边形建模与 GDScript 场景搭建；材质以 StandardMaterial3D、程序化噪声着色器、发光材质和代码生成的纹理为主。
- 星空为三层程序化星场加 2600 颗 3D 星点；太阳黑子、日珥、彗尾、云层、盐壳裂谷与植物均为自定义着色器或程序几何。
